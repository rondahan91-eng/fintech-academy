# סכמת שבוע

כל שבוע בקורס הוא תיקייה `content/week-NN/` עם מבנה קבוע. הסכמה קיימת כדי ששלושה דברים ייגזרו מהתוכן במקום להיות ניחוש: **דרישות הפלטפורמה**, **הטסטים**, ו**מה שה-AI מלמד**.

## המבנה

```
content/
  _schema/
    README.md            ← המסמך הזה
  _shared/
    persona.yml          ← זהות המנהל, טון, וכללים שחלים על כל השבועות
    lib/                 ← קוד תשתית שהפלטפורמה מזריקה לסביבת ההרצה
      account.py
  week-01/
    meta.yml             ← מטא-דאטה: סילבוס, שעות, תלויות
    task.md              ← המשימה כפי שהתלמיד רואה אותה
    starter.py           ← קוד הפתיחה בעורך
    tests_visible.py     ← מה שהתלמיד יכול להריץ בעצמו
    tests_hidden.py      ← מה שקובע ניקוד
    manager.yml          ← תדריך ההוראה של המנהל לשבוע הזה
    rubric.md            ← מה נחשב איכות קוד בשבוע הזה
    lesson-plan.md       ← [אופציונלי] מערך שיעור למורה
    customer.md          ← [אופציונלי] פניית לקוח מהקטלוג
```

`customer.md` אופציונלי — שבועות 1–3 הם קליטה ואין בהם עדיין פניות.

## `lesson-plan.md`

מערך למפגש בכיתה. **הקובץ היחיד בסכמה שהתלמיד לעולם לא רואה** — הוא
נכתב למורה בלבד.

חייב להיפתח בטבלת **חלוקת עבודה בין הכיתה למערכת**. החלוקה קבועה
לכל השנה:

| | מלמד | מסייע |
|---|---|---|
| **המורה** | פייתון — מושגי השבוע, תחביר, דוגמאות | תקלות סביבה |
| **אלעד** | פיננסים ובנקאות | תקיעות תכנותיות, דרך סולם הרמזים |

**אלעד הוא בנקאי שיודע לתכנת, לא מורה לתכנות.** התלמיד מגיע למערכת
עם היכולת התכנותית ופוגש שם את ההקשר הפיננסי — לא להפך.

שתי דרכים לשבור את זה, ושתיהן קורות בקלות: אם המורה מלמד ברוטו ונטו,
אלעד הופך לקישוט ואין סיבה לדבר איתו. אם אלעד מלמד תחביר, השיעור
הפרונטלי מתייתר. **כל צד מחזיק תחום שהשני לא נוגע בו.**

הדוגמאות בחלק הפרונטלי צריכות להיות **דומות למשימה בבנק ולא זהות
לה** — אותה מיומנות על תוכן אחר. התלמיד מגיע עם היכולת, בלי הפתרון.

כולל גם **גבולות שליליים** — מה במפורש *לא* מלמדים היום ולאיזה שבוע
זה שייך. בלעדיהם המורה נגרר לשאלה של תלמיד סקרן ושורף תוכן של שבוע
מאוחר יותר.

לא כל שבוע זקוק למערך. שבוע שהוא המשך ישיר של קודמו יכול להסתדר בלי.

## `meta.yml`

מקשר את השבוע לתכנית הלימודים ולמנגנוני המשחק. **זהו הקובץ היחיד שהפלטפורמה קוראת כדי לדעת מה לעשות עם השבוע.**

| שדה | משמעות |
|---|---|
| `week` | מספר השבוע (1–30) |
| `syllabus.chapter` | פרק בתכנית הלימודים 11.004 |
| `syllabus.items` | מספרי הסעיפים המכוסים — **מזין את טבלת הכיסוי ב-SPEC** |
| `hours` | שעות מוקצות (2 בפריסה הנוכחית) |
| `python_concepts` | רשימת מושגים תכנותיים |
| `financial_concepts` | רשימת מושגים פיננסיים |
| `deliverable` | שם התוצר |
| `is_star` | האם התוצר נכנס לתשתית המערכת (⭐ בלולאה הסגורה) |
| `rank_gate` | דרגה שנפתחת בסיום, או `null` |
| `depends_on` | שבועות שהתלמיד חייב לסיים לפני |
| `xp` | XP למשימה שעברה |
| `injects` | קובצי תשתית מ-`_shared/lib/` שיורצו לפני קוד התלמיד |
| `fixture` | הנתונים הקבועים של המשימה. **מקור אמת אחד** ל-task, tests ו-manager |

### `injects` — קוד תשתית

קבצים ב-`content/_shared/lib/` שהפלטפורמה מריצה **באותו namespace** לפני
קוד התלמיד, כך שמה שהם מגדירים זמין בלי `import`.

כללים:
1. **התלמיד משתמש, לא כותב.** קוד תשתית מספק מה שטרם נלמד לכתוב.
2. **המימוש לא מוצג לתלמיד** — רק הממשק, ב-`task.md`. הצגת קוד עם תחביר
   שלא נלמד מבלבלת יותר משהיא מלמדת.
3. **שם עם קו תחתון מוביל = פרטי.** `_balance` מסמן "אל תיגע" בלי לאכוף.
4. קוד תשתית שנטען פעם אחת **זמין גם בשבועות הבאים** אם הם מציינים אותו
   ב-`injects` שלהם.

## `task.md`

הניסוח שהתלמיד רואה. **בגוף שני, בהקשר של הבנק, בלי ז'רגון פדגוגי.** לא "בשיעור זה נלמד" אלא "הצוות צריך ממך".

חייב לכלול: מה לבנות, מה נבדק, ומה מותר להיעזר בו.

## `starter.py`

קוד פתיחה בעורך. לתלמידים ללא רקע — כולל הערות שמסמנות איפה לכתוב. **אסור שיכיל את הפתרון בהערה.**

## `tests_visible.py` / `tests_hidden.py`

**חוזה הטסטים:** כל פונקציה ששמה מתחיל ב-`test_` מורצת. נכשלת = `AssertionError`. הודעת השגיאה מוצגת לתלמיד כמות שהיא, ולכן **היא צריכה להיות מנוסחת כמשוב, לא כשגיאה טכנית**.

לטסטים זמינים:

| משתנה | תוכן | מאיזה שבוע |
|---|---|---|
| `OUTPUT` | כל מה שהתלמיד הדפיס, כמחרוזת אחת | 1 |
| `LINES` | אותו דבר, מפוצל לשורות | 1 |
| `VARS` | המשתנים של התלמיד אחרי ההרצה, כמילון | 3 |

`VARS` נדרש משבוע 3, שכולו על משתנים וטיפוסים ואי אפשר לבדוק אותו
דרך הפלט בלבד. שימוש טיפוסי:

```python
assert isinstance(VARS["account_number"], str)
```

**שבוע שמשתמש ב-`VARS` חייב לקבוע שמות משתנים מדויקים ב-`task.md`.**
בלי זה הטסט שביר והתלמיד צודק.

- **גלויים** — התלמיד מריץ כמה שירצה. מכסים את המקרה הבסיסי בלבד.
- **נסתרים** — קובעים ניקוד. מכסים גם מקרי קצה. **לא נחשפים** אלא בקניית הפריט מהחנות.

## `manager.yml`

התדריך שממנו נבנה ה-system prompt של המנהל לשבוע הזה. **זהו הקובץ הכי חשוב בסכמה**, כי המנהל הוא ערוץ ההוראה של התוכן הפיננסי — התלמידים לומדים את המושגים ממנו, לא לפני התרגול.

| שדה | משמעות |
|---|---|
| `teaches` | המושגים שהוא אחראי ללמד השבוע, עם ההסבר, האנלוגיה והתפיסה השגויה הנפוצה |
| `must_not_reveal` | מה אסור לו למסור בשום ניסוח |
| `understanding_signals` | איך נראה תלמיד שהבין — מתי לעבור הלאה |
| `hint_ladder` | סולם רמזים מדורג. **לעולם לא מדלגים שלב** |
| `opening` | ההודעה שפותחת את השבוע |
| `on_stuck` | מה לעשות אחרי X דקות בלי התקדמות |

> **הכלל שלא נשבר:** המנהל מלמד, משוחח ומרמז. **הוא לא קובע נכונות ולא מזין ציון** — זה תפקיד הטסטים. ראה SPEC פרק 7.

## `rubric.md`

מה נחשב "איכות קוד" בשבוע הזה — הקריטריון ל-150 ₪ בתגמול הביצועים. **משתנה משבוע לשבוע:** בשבוע 1 זה שמות משתנים; בשבוע 20 זה היעדר כפילות.

## כללי עבודה

1. **`meta.yml` הוא מקור האמת לכיסוי הסילבוס.** טבלת הכיסוי ב-SPEC נגזרת ממנו, לא להפך. אם שינית שבוע — עדכן את `meta.yml` ואת הטבלה תבנה מחדש.
2. **טסט נסתר שנכשל חייב להסביר מה חסר, בלי לומר איך לתקן.** "לא מצאתי את סכום הנטו בפלט" — לא "צריך להוסיף `print(4990)`".
3. **מספר בטסט = מספר ב-`task.md`.** אם הם נפרדו, התלמיד צודק והטסט שגוי.
4. **שבוע ⭐ נכנס לייצור.** הקוד של התלמיד ירוץ במערכת. הטסטים הנסתרים שם חייבים לכסות מקרי קצה, אחרת התלוש שלו יישבר.
